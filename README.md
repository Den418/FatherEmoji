# Отец эмодзи

Бот для создания кастомных эмодзи-паков в Telegram (hydrogram).

## Запуск

```
pip install -r requirements.txt
python selftest.py     # проверит ffmpeg, vtracer, rlottie и шрифты
python main.py
```

Токены берутся из переменных окружения `API_ID`, `API_HASH`, `BOT_TOKEN`, `DB_PATH`.
Значения по умолчанию в `config.py` лучше убрать из кода (см. раздел «Безопасность»).

База `bot_users.db` и файл сессии подхватываются из папки запуска, миграции не нужны.

## Что умеет

**Создать пак.** Ссылка, название, базовый эмодзи, дальше выбор режима:

- **Обычный режим.** Картинки, GIF, видео до 3 секунд, `.tgs`, чужие эмодзи и ссылки на чужие паки.
- **Текстовые эмодзи.** Вы пишете слово или фразу, бот рисует эмодзи на цветном фоне. Есть эффекты (свечение, обводка, тень, градиенты) и анимации.

Тот же выбор появляется при «Редактировать → Добавить эмодзи».

**Доп. функции** (кнопка в главном меню):

- **Перекраска пака.** Копия пака в новом цвете, исходный не меняется.
- **Достать файл эмодзи.** Присылает исходный `.webp`, `.tgs` или `.webm`.

## Текстовые эмодзи

После текста бот показывает превью с кнопками. Каждая правка перерисовывает его в том же сообщении, а у анимированных стилей превью это зацикленный ролик.

**Оформление:** цвет фона и текста (палитра, свой HEX, «без фона»), 13 шрифтов с кириллицей (папка `fonts/`, лицензия OFL), форма (скруглённый квадрат, круг, квадрат, без фона). Длинный текст сам делится на строки (до 5 строк, до 60 символов), слова не рвутся.

**Эффекты** (кнопка «Эффекты»):

- свечение трёх уровней с отдельным цветом;
- обводка трёх толщин с отдельным цветом;
- тень;
- градиент текста и градиент фона, второй цвет задаётся отдельно.

**Анимации** (кнопка «Анимация», три скорости): пульс, качание, прыжок, дрожь, мигание, пульс свечения, радуга, волна (буквы бегут по очереди), печать (буквы набираются). У каждого цикла на нулевом кадре виден весь текст, поэтому превью эмодзи в списке выглядит нормально.

**Форматы** (кнопка «Формат»):

| Формат | Что это | Особенности |
|---|---|---|
| Статичный | webp 100×100 | эффекты есть, анимации нет |
| Векторный | `.tgs` из контуров шрифта | лёгкий (1-30 КБ), чёткий, анимации; свечение собирается из полупрозрачных слоёв, поэтому выглядит как мягкий ореол |
| Видео | `.webm` 100×100 | настоящее размытие для свечения, любые анимации, файл тяжелее |

### Почему формат пака нельзя менять

Формат пака задаётся его первым эмодзи, Telegram не смешивает форматы. Если в пак раньше добавляли GIF или видео, он видео-пак, и текст в него может попасть только как видео. Раньше бот молча подстраивался под пак. Теперь в панели виден замок (🔒) и пояснение, а кнопка «Новый пак» одним нажатием создаёт отдельный пак с форматом «Статичный» по умолчанию.

Если вектор не влезает в 64 КБ, бот по очереди отключает тень, часть слоёв свечения и само свечение и пишет, что именно пришлось убрать. Если не помогает и это, предлагает формат «Видео».

Настройки запоминаются на время работы бота, следующий текст можно присылать сразу.

## Перекраска

Два режима:

- **Один цвет.** Всё становится оттенками выбранного цвета, контуры и тени остаются.
- **Сдвиг оттенка.** Разноцветные эмодзи остаются разноцветными, основной цвет меняется на выбранный.

Работает для статики, анимаций `.tgs` и видео `.webm`.

## Долгие операции и лимиты Telegram

Telegram ограничивает частоту `addStickerToSet`: на больших паках прилетает flood wait на минуты. Поэтому перекраска и копирование работают как задачи (`jobs.py`):

- **Паузы.** При перекраске после каждых `BATCH_SIZE` (8) добавленных эмодзи бот ждёт `BATCH_PAUSE` (280 секунд). Оба значения лежат в `config.py`. Если Telegram сам заставил ждать 20 секунд и больше, счётчик пачки обнуляется, лишняя пауза не нужна.
- **Оставшееся время.** В сообщении с прогрессом видно полосу, счётчик и примерное время до конца. Оно считается по среднему времени на эмодзи плюс все ещё предстоящие паузы.
- **Обратный отсчёт.** Во время паузы и flood wait сообщение показывает, сколько ждать осталось, а не молчит.
- **Остановка.** Под сообщением кнопка «Остановить». Уже готовые эмодзи остаются в новом паке, бот пришлёт ссылку.
- **Фоновая работа.** Перекраска идёт отдельной задачей, бот в это время отвечает остальным. На пользователя одна долгая операция за раз.

Копирование пака тоже показывает прогресс, оставшееся время, отсчёт ожидания Telegram и кнопку остановки, но проактивных пауз в нём нет: бот ждёт только тогда, когда Telegram об этом попросил.

## Векторизация

Три режима (выключено, всё, спрашивать каждый раз) переключаются кнопками, как раньше. Что изменилось в самом алгоритме (`vector.py`):

- Края и прозрачность больше не тянут за собой «мусорные» цвета, поэтому пропали белые пятна и чёрные обводки вокруг теней.
- Полупрозрачные области (стекло, свечение) рисуются отдельным слоем с настоящей прозрачностью.
- Палитра подбирается по картинке: плоским эмодзи хватает 6-12 цветов, фото получают до 48.
- Маленькие картинки растягиваются на весь холст 512×512.
- Файлы получаются в 2-4 раза легче, а значит влезают в 64 КБ с большей детализацией.
- Качество подбирается двоичным поиском, обычная картинка считается 2-4 секунды.

## Тяжёлые стикеры

Раньше при копировании Telegram отвечал ошибкой, если файл не подходил как есть. Теперь:

1. Бот пробует добавить эмодзи как есть (быстрый путь).
2. Если не вышло, скачивает файл и приводит его к формату пака (`media.adapt`):
   - статика: webp 100×100;
   - анимация: `.tgs` до 64 КБ, лишнее убирается из JSON без потери кадров;
   - видео: webm 100×100 до 256 КБ, качество и частота кадров снижаются ступенями.
3. Форматы конвертируются друг в друга. Видео-стикер в статичный пак даст кадр, `.tgs` в видео-пак даст ролик, картинка в анимированный пак даст вектор.
4. Если анимация слишком сложная для `.tgs`, остаётся один кадр вектором, бот об этом пишет.

В итоге сообщается, сколько эмодзи удалось подогнать, а ошибки названы простыми словами.

## Зависимости

- `vtracer` нужен только для векторизации картинок. Без него бот работает, но векторный режим сообщит об ошибке. Текстовые эмодзи от него не зависят.
- `rlottie-python` нужен для сжатия анимаций через кадры, конвертации `.tgs` в видео или статику и перекраски видео. Без него эти пункты отключаются, остальное работает.
- ffmpeg берётся из `imageio-ffmpeg`, отдельная установка не нужна. Нужна сборка с `libvpx-vp9` (видео-эмодзи) и желательно `libx264` (ролики-превью анимаций; без него превью показывается картинкой). `selftest.py` проверяет оба кодека.

## Безопасность

В `config.py` значения `API_HASH` и `BOT_TOKEN` прописаны прямо в коде как значения по умолчанию. Если репозиторий или архив кто-то видел, перевыпустите токен в @BotFather (`/revoke`), а новые значения передавайте через переменные окружения.
